# Анализ продаж интернет-магазина

Учебный проект на синтетических данных: реляционная база SQLite, восемь
аналитических SQL-запросов и два графика выручки. При расчёте выручки учитываются
только заказы со статусом `completed`; цены в таблицах хранятся в копейках.

## Структура

```text
result/
├── README.md
├── requirements.txt
├── .gitignore
├── visualize_revenue.py      # Построение графиков из SQLite
├── data/
│   ├── csv/                  # Таблицы в CSV с заголовками, UTF-8
│   └── online_store.sqlite   # Готовая база для запросов и визуализации
├── sql/
│   ├── create_tables.sql     # Пересоздание таблиц, ограничений и индексов
│   ├── insert_data.sql       # Заполнение синтетическими данными
│   └── queries.sql           # Запросы Q1–Q8
├── er_diagram/               # Исходник draw.io и изображение ER-диаграммы
├── output/                   # Графики в PNG и SVG
└── report/                   # Отчёт
```

## Данные и их обновление

Для воспроизведения базы исходными считаются `sql/create_tables.sql` и
`sql/insert_data.sql`. Файл `data/online_store.sqlite` — готовая база, построенная
по этим скриптам, а `data/csv/` содержит те же таблицы в переносимом формате.
Python-скрипт читает только SQLite; изменения CSV сами по себе на графики не влияют.

В наборе 50 покупателей, 8 категорий, 40 товаров, 150 заказов и 300 позиций заказов.
При изменении набора обновите SQL-вставки, пересоздайте базу, экспортируйте таблицы
в соответствующие CSV (например, через DBeaver с заголовками и кодировкой UTF-8)
и заново постройте графики. Автоматической синхронизации этих форматов нет.

## Быстрый запуск

Нужны Python 3.11+ и библиотека из `requirements.txt`.
Проверено с Python 3.14.7, SQLite 3.53.4 и Matplotlib 3.11.2.
Команды ниже выполняются из корня проекта в macOS/Linux:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python visualize_revenue.py
```

Готовая база уже включена в проект, поэтому для построения графиков её не нужно
создавать заново. Скрипт использует Q2 и Q5 из `sql/queries.sql`, сверяет общую
выручку по категориям и месяцам и сохраняет четыре файла:

- `output/category_revenue.png`
- `output/category_revenue.svg`
- `output/monthly_revenue.png`
- `output/monthly_revenue.svg`

Повторный запуск перезаписывает эти графики. Пути вычисляются относительно
расположения скрипта, поэтому запуск возможен и из другой рабочей папки.

## Восстановление базы из SQL

Для схемы с таблицами `STRICT` нужен SQLite 3.37 или новее.
Для следующих команд также нужна консольная программа `sqlite3`:

```bash
sqlite3 --version
sqlite3 -bail data/online_store.sqlite ".read sql/create_tables.sql" ".read sql/insert_data.sql"
sqlite3 -readonly data/online_store.sqlite "PRAGMA integrity_check; PRAGMA foreign_key_check;"
```

**Команда восстановления удаляет существующие таблицы и их данные.** Если база
содержит собственные изменения, сначала сохраните её копию. Повторно запускать
`insert_data.sql` без пересоздания таблиц не следует: идентификаторы уже существуют.
При успешной проверке целостности выводится `ok`, а проверка внешних ключей
не возвращает строк.

Все аналитические запросы можно выполнить так:

```bash
sqlite3 -readonly -header -column data/online_store.sqlite ".read sql/queries.sql"
```

## Работа в DBeaver

Создайте подключение SQLite и выберите `data/online_store.sqlite` в своей копии
проекта. Затем открывайте файлы из `sql/` и выбирайте это подключение для выполнения
запросов. Для пересоздания базы выполняйте сначала `create_tables.sql`, затем
`insert_data.sql` целиком.

Каталог `.dbeaver/` и файл `.project` содержат локальные настройки, включая путь
к базе на конкретном компьютере, поэтому исключены из Git. После переноса всего
проекта в другое место путь в подключении DBeaver нужно выбрать заново.

## Материалы для сдачи

В проект включаются SQL, CSV, готовая база, ER-диаграмма, графики и отчёт.

Окружение `.venv/`, кэши Python и Matplotlib, служебные файлы macOS и настройки
DBeaver исключены из Git. База и итоговые графики намеренно сохраняются в проекте,
чтобы результаты можно было просмотреть без повторного запуска.
